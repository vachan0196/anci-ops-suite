Q.5.3a-2b-1 - mutation demonstration
Date: 2026-09-13
Base: 53a3b3d

SUBJECT OF THE MUTATION
  apps/api/routers/auth.py, the explicit dict in _to_user_out:
      "email_verified_at": user.email_verified_at,
  commented out, then restored.

WHY THIS MUTATION
  UserOut declares email_verified_at with default None. If the dict key is
  omitted, every response reports null regardless of the user's real state.
  No existing test detects this: none asserts a key count or a closed key set
  on UserOut, and the only exact-dict assertion on /auth/me covers the EMPLOYEE
  branch (test_phase_k1_employee_identity_hardening.py:259). The full suite
  would have stayed green at 1069.

BASELINE ATTEMPT - DISCARDED
  A first run was made before the edit was applied. The build reported
      => CACHED [5/6] COPY apps ./apps        0.0s
  and returned 6 passed. CACHED on that layer means apps/ was byte-identical to
  the previous build, so the image did not contain the mutation. Result void.
  The api service has no source bind mount; the CACHED line on COPY apps is the
  reliable indicator of whether a source edit reached the image.

  mutation does not break.

  right reason, but a raised exception is a weaker signal than an assertion.
  T3 is the assertion-level proof.
