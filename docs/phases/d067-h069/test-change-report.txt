Method and denominator
Compared function bodies and assertions against git show e9716b1:<path>, followed
local helper calls transitively, and checked imports of changed shared helpers.
100 existing tests are listed individually below: 56 retained-name changed bodies,
one renamed Q3.1 body-token test, and 43 unchanged bodies affected through helpers.
The ten changed external callers of the T0 legacy-token helper are included in the
56, not counted twice. The other T0 importers import helpers that did not change.
None of these 100 tests is parametrized, so the listed path::function is its full
node ID. New parametrized tests are accounted for separately in the suite delta.

The report distinguishes original proof from credential transport. H069 deliberately
retires the body-token compatibility contract; only the renamed Q3.1 case replaces
that behavior. This is not a claim that its old success assertions survived.

Set-Cookie source and repairs
HTTPX response.cookies is parsed from that response's Set-Cookie headers. The new
test-only issued_refresh_token(response, client, previous=...) reads that value,
requires it to be nonempty, verifies client receipt, and, when previous is supplied,
requires a changed value. The response body is not modified; some test helpers keep
the issued value under a refresh_token key in their own local return dictionary.
Retained original/rotated values are captured before subsequent cookie swaps.

Three weakened assertions were identified in the earlier patch:
1. Q3.1 successful cookie refresh: response/client equality became cookie presence.
   Repaired before this continuation by reading Set-Cookie and checking difference
   from the original plus equality with the client's received value.
2. Q2 cookie refresh/logout: the expected response-issued value was replaced by
   reading the client cookie itself, making equality tautological. Repaired here
   with issued_refresh_token(refresh_response, client, previous=original_refresh).
3. Q5.1 login without active 2FA: nonempty refresh value became cookie-name presence.
   Repaired here with issued_refresh_token(response, client).
Q5.1 2FA verification's nonempty-value proof had already been restored in the prior
1069 run; this continuation additionally checks client receipt through the helper.
The wider inventory also exposes an issuance-provenance weakness in the cookie-jar
substitutions: a retained predicate can accidentally check an older cookie when a
response omits Set-Cookie. This matters particularly to rotated-value leakage tests,
employee-login leakage tests and two-login leakage tests. Their predicates were not
deleted, but the assertion subject was no longer independently tied to the issuing
response. All affected issuance reads now have a Set-Cookie/client-receipt guard;
the entry verdicts distinguish re-sourced predicates from a proved response source.
No production behavior was changed for any of these repairs.

Other existing coverage already checked client receipt: Q2's admin lifecycle reads
the client cookie and requires a changed value; the new H069 lifecycle [admin] and
[employee] cases also resolve the client's changed value to the active child session.
Thus the whole-suite proof was not absent, even though the two local proofs weakened.
